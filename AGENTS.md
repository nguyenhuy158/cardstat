# Repository Guidelines

## Project Structure & Module Organization

cardstat is a credit-card spending tracker: import bank statements (PDF/CSV),
auto-categorize transactions, and show stats, charts and budgets. It is a
Next.js 16 App Router app deployed to Cloudflare Workers through
`@opennextjs/cloudflare`, with Cloudflare D1 for storage and the shared huyab
SSO cookie (`huyab_sso`) for auth. The server side is layered (clean
architecture): `domain` (pure) <- `application` (use cases) <-
`infrastructure` (D1, SSO, PDF) <- `app` (routes/UI).

Folder structure:

```text
src/
  domain/                      # Pure rules, no IO
    entities/                  #   Transaction, Upload
    ports/                     #   TransactionRepository interface
    services/                  #   Statement text parser, categorize, insights
  application/use-cases/       # One file per use case (import, list, stats, budgets...)
  infrastructure/
    auth/                      #   SSO session (@huyab/sso) -> user id, requireUser()
    parsing/                   #   PDF text extraction (unpdf)
    persistence/               #   D1 repository + getRepository()
  app/                         # Next.js App Router
    (app)/                     #   Authenticated pages: overview, charts, transactions, upload
    api/                       #   Route handlers (thin: requireUser -> use case -> JSON)
    login/                     #   SSO login page
    globals.css                #   Global styles + base rules
    *.tsx / *.ts               #   Shared client components and helpers (colors, format...)
  styles/tokens.css            # Design tokens (ui-kit structure, cardstat palette)
migrations/                    # D1 SQL migrations (applied by hand, see README)
scripts/                       # CLI helpers (upload/stats/list) + post-deploy smoke test
public/                        # Static assets + service worker (sw.js)
cloudflare-env.d.ts            # Generated by `pnpm cf-typegen` (committed for CI)
wrangler.jsonc                 # Worker config: D1 binding, route, SSO_ISSUER
open-next.config.ts            # OpenNext Cloudflare adapter config
```

## Build, Test, and Development Commands

- `pnpm install`: install project dependencies.
- `pnpm dev`: start the Next.js dev server on `localhost:3000`.
- `pnpm build`: Next.js production build.
- `pnpm check`: generate Next route/env types (`next typegen`), then
  `tsc --noEmit`.
- `pnpm lint`: ESLint with `eslint-config-next` (core-web-vitals + TS).
- `pnpm preview`: OpenNext Cloudflare build + local Workers preview.
- `pnpm cf-typegen`: regenerate `cloudflare-env.d.ts` after changing bindings.
- `pnpm upload <file>` / `pnpm stats` / `pnpm tx`: CLI helpers; need
  `HUYAB_SSO_COOKIE` (see README).
- `node scripts/smoke.mjs [baseUrl]`: smoke test a deployment.
- `pnpm e2e`: OpenNext build, apply D1 migrations locally, start a fake SSO
  JWKS + `wrangler dev` (same worker as `pnpm preview`), then run the Chromium
  smoke suite `e2e/ui-smoke.mjs` (playwright-core). Set
  `PLAYWRIGHT_CHROMIUM_PATH` if no Chromium/Chrome is found.
- `pnpm e2e:prod`: read-only browser smoke against
  https://cardstats.huyab.click (GET `/`, `/login`, `/api/stats`,
  `/api/transactions`, `/manifest.webmanifest`; no login, no writes).
- `pnpm exec wrangler d1 migrations apply db --local|--remote`: apply D1
  migrations (production is never migrated automatically).

Deploy: Cloudflare Workers Builds deploys every push to `main`. Do not run
`pnpm deploy` and do not add a deploy step to CI.

Use `pnpm` for all package commands.

## Coding Style & Naming Conventions

Use TypeScript with strict compiler settings and the `@/*` path alias. Prefer
named exports for utilities and `import type` for types. Two-space
indentation, double quotes. Files use kebab-case (`transaction-detail-modal.tsx`);
React components use PascalCase names. Avoid magic strings and numbers;
extract them into named constants. Keep layering: domain code has no IO,
route handlers stay thin and always call `requireUser()` (it is the security
boundary; page-level redirects are only UX). Every SQL query must filter by
`user_id`. Linting stays on ESLint (`eslint-config-next`) rather than Biome so
the Next.js and React hooks rules keep running.

Styling: Tailwind CSS v4. Prefer the design-token utilities from
`src/styles/tokens.css` (`bg-bg`, `bg-surface`, `bg-surface-muted`,
`border-border`, `text-fg`, `text-fg-muted`, `text-primary`, `ring-ring`, ...)
over raw palette classes for new code. Dark mode is the `.dark` class on
`<html>`, set from `prefers-color-scheme` by the inline script in
`src/app/layout.tsx`. Category/series chart colors live in `src/app/colors.ts`
(validated palette, do not change casually).

## Testing Guidelines

There is no unit test suite yet. Verify changes with `pnpm check`,
`pnpm lint`, `pnpm build` and `pnpm e2e` (CI runs the E2E job on every push
and PR). The dev E2E signs its own SSO JWT with `startSsoMock` from
`@huyab/e2e` (`SSO_ISSUER` is overridden with `wrangler dev --var`) and writes
only to local D1; `pnpm e2e:prod` and `scripts/smoke.mjs` must stay read-only. If tests are added, use Vitest with files colocated beside
the module, prioritizing `src/domain/services/` (statement parsing,
categorization, insights).

## Commit & Pull Request Guidelines

Use concise Conventional Commits, for example `feat: add budget alerts` or
`fix: parse negative amounts in statements`. Pull requests should include a
short summary, check/lint/build results, and screenshots for visible UI
changes. Remember to apply new D1 migrations to production by hand.
